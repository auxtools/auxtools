# Restricting the profile report webview to its own scripts

The VS Code extension displays a profile report, an HTML page generated by the launcher, inside a
webview. Because the report embeds profile data containing names from the world, that data could
contain markup.

When writing the report's JSON data, the launcher escapes every `<` character as `\u003c`, ensuring
that every `<script>` and `<style>` tag in the page belongs to the page itself. `confined` in
`editors/vscode/report.js` then generates a random nonce, injects a Content Security Policy allowing
only scripts and styles with that nonce, and adds the nonce to every `<script>` and `<style>` tag.
The policy is placed immediately after `<head>`. If a page has no `<head>`, the policy is placed at
the beginning of the document and none of its scripts or styles run.

The tag rewrite is safe only because the launcher escapes `<`. If the launcher stopped escaping `<`,
embedded world data could inject a `<script>` tag that would then receive the nonce.

## Applies to

- `editors/vscode/report.js`: `confined`
- `auxtools-cli/src/profile.rs`: report writer
